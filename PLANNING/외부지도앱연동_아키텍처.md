## 2. 데이터 흐름 상세 (케이스별)

### Case A: Google Maps 공유 버튼 → PlaceCards

```
1️⃣ 사용자 액션
   Google Maps 앱 → 장소 선택 → [공유] 버튼
   
2️⃣ iOS Share Sheet
   "PlaceCards" 앱 선택
   
3️⃣ PlaceCards 앱이 받는 데이터
   URL: https://www.google.com/maps/place/ChIJ1234567890/@37.4979,127.0663
   
4️⃣ SceneDelegate에서 처리
   • URL에서 placeId 추출 (정규표현식)
   • placeId = "ChIJ1234567890"
   
5️⃣ Google Places API 호출
   googleService.getDetails(placeId: "ChIJ1234567890")
   └─ 응답: {name, address, rating, reviewCount, hoursDetail, ...}
   
6️⃣ PlaceCard 생성
   • 모든 필드 채우기
   • 출처: SourceType.googlePlacesAPI
   • 신뢰도: 1.0 (API에서 직접)
   
7️⃣ 저장 및 표시
   storageService.save(placeCard)
   └─ SwiftData에 저장
   └─ UI 업데이트 (새 PlaceCard 표시)
```

---

### Case B: Google Takeout JSON → PlaceCards (배치)

```
1️⃣ 사용자 액션
   takeout.google.com → Google Maps 선택 → 다운로드 (.zip)
   
2️⃣ 파일 구조
   takeout-{날짜}.zip
   └─ Takeout/Google Maps/Saved Places.json
   
3️⃣ JSON 형식 (GeoJSON)
   {
     "features": [
       {
         "geometry": { "coordinates": [127.0663, 37.4979] },
         "properties": {
           "title": "스타벅스 강남역점",
           "address": "서울시 강남구 테헤란로 301",
           "placeID": "ChIJ1234567890",
           "rating": 4.5
         }
       }
     ]
   }
   
4️⃣ PlaceCards 앱에서 임포트
   [Settings] → [Import] → [JSON 파일 선택]
   
5️⃣ 파일 파싱 및 검증
   • JSON 유효성 확인
   • features[] 개수 확인
   • 필수 필드(title, address) 확인
   
6️⃣ 배치 처리 (반복)
   for each feature in features:
     a. 기본 정보 추출 (제목, 주소, 좌표)
     b. Google Places API로 상세정보 보강 (선택사항)
     c. PlaceCard 생성
     d. SwiftData에 저장
     e. 진행률 업데이트 (n/total)
   
7️⃣ 완료 알림
   "50개 장소가 추가되었습니다"
```

---

### Case C: Naver Map 공유 버튼 → PlaceCards

```
1️⃣ 사용자 액션
   Naver Map 앱 → 장소 검색 → [공유]
   
2️⃣ iOS Share Sheet
   "PlaceCards" 선택
   
3️⃣ PlaceCards가 받는 데이터
   URL: https://map.naver.com/v5/search/스타벅스+강남역점
   또는
   URL: nmap://place?id=12345678&appname=com.example.placecards
   
4️⃣ URL 파싱
   • 쿼리 파라미터에서 placeId 추출
   • 또는 placeId를 Naver 검색 실행
   
5️⃣ Naver API 호출 (백엔드 프록시)
   naverService.search(query: "스타벅스 강남역점")
   └─ 응답: {title, address, coordinates, phone, category}
   
6️⃣ Google API로 보강
   googleService.search(query: "스타벅스 강남역점")
   └─ 응답: {rating, reviewCount, hoursDetail, amenities, website}
   
7️⃣ PlaceCard 생성 (통합)
   • Naver + Google 정보 병합
   • 출처 기록: [Naver API, Google API]
   
8️⃣ 저장
   storageService.save(placeCard)
```

## 3. 필요한 API 엔드포인트

### Google Places API
```
POST https://places.googleapis.com/v1/places:searchText
POST https://places.googleapis.com/v1/places/{placeId}
```

### Naver Map API (프록시 경유)
```
POST /api/naver/search
  body: { query, language }
  
POST /api/naver/details
  body: { placeId }
```

### PlaceCards App URL Scheme
```
placecards://import/google?placeId=ChIJ1234567890
placecards://import/naver?placeId=12345678
placecards://import/json?data={base64_encoded}
placecards://import/url?url=https://...
```

## 4. 데이터 중복 방지

### 같은 장소를 여러 번 임포트한 경우

```
PlaceCard 모델에 추가:
  • externalIds: [String: String]  // {"google": "ChIJ...", "naver": "1234"}
  • lastImportedFrom: SourceType
  • importedDate: Date

임포트 전 확인:
  1. 새로 가져오는 장소의 좌표 및 이름으로 기존 PlaceCard 검색
  2. 일치하는 카드가 있으면:
     a. externalIds에 새 ID 추가 (구글+네이버 병합)
     b. 정보 업데이트 (최신 정보로)
     c. 새 PlaceCard 생성하지 않음
  3. 일치하는 카드가 없으면:
     a. 새 PlaceCard 생성
```

**구현**:
```swift
func importPlaceCard(_ placeCard: PlaceCard) async throws {
    // 기존 카드와 일치 여부 확인
    let existing = try storageService.searchByCoordinates(
        coordinates: placeCard.coordinates,
        radiusKm: 0.1  // 100m 범위
    )
    
    if let existingCard = existing.first,
       similarity(existingCard.name, placeCard.name) > 0.8 {
        // 병합
        var updated = existingCard
        updated.externalIds[sourceType.rawValue] = placeCard.sources[0].id
        updated.nameByLanguage.merge(placeCard.nameByLanguage) { $1 }
        updated.addressByLanguage.merge(placeCard.addressByLanguage) { $1 }
        try storageService.update(updated)
    } else {
        // 새로 추가
        try storageService.save(placeCard)
    }
}
```

## 5. 에러 처리 전략

| 에러 | 원인 | 대응 |
|------|------|------|
| **파일 없음** | 사용자가 잘못된 파일 선택 | "유효한 JSON 파일을 선택하세요" |
| **JSON 손상** | Takeout 파일 손상 | "파일 재다운로드 필요" |
| **API 실패** | Google/Naver API 오류 | 재시도 (Exponential Backoff) |
| **좌표 없음** | 오래된 Takeout 파일 | 기본 정보만으로 생성 |
| **중복 감지** | 같은 장소 여러 번 임포트 | 병합 또는 스킵 옵션 제시 |
| **네트워크 오류** | 인터넷 끊김 | "인터넷 연결 확인" |

## 6. 보안 고려사항

### 데이터 보호
- ✅ JSON 파일은 로컬에서만 처리 (업로드 안 함)
- ✅ Google Takeout 파일은 사용자가 관리
- ✅ API 키는 Keychain에 저장 (평문 저장 금지)

### 권한 관리
- ✅ 파일 선택: 사용자 명시적 승인
- ✅ 카메라/사진: 필요할 때만 요청
- ✅ 위치: 지도 표시에만 사용

## 7. 성능 최적화

### 대용량 파일 처리 (500+ 장소)

```swift
// ✅ Streaming 처리 (메모리 효율)
func importLargeJSONFile(_ url: URL) async throws {
    let stream = try InputStream(url: url)
    let decoder = JSONDecoder()
    
    while let feature = try decoder.decode(
        GeoJSONFeature.self,
        from: stream
    ) {
        let placeCard = try createPlaceCard(feature)
        try storageService.save(placeCard)
        
        // UI 업데이트
        DispatchQueue.main.async {
            self.importProgress = Double(processed) / Double(total)
        }
        
        // 메모리 해제 및 짧은 지연
        try? await Task.sleep(nanoseconds: 10_000_000)
    }
}

// ✅ 배치 처리 (API 호출 효율)
// 100개씩 묶어서 처리
let batches = placeCards.chunked(into: 100)
for batch in batches {
    let tasks = batch.map { place in
        googleService.getDetails(placeId: place.id)
    }
    
    let results = try await [Task]
        .concurrentlySettledAwaitAll(tasks)
}
```
