# 2. PlaceCard 데이터 모델

## 2.1 핵심 구조

PlaceCard는 여행/나들이 중 발견한 하나의 장소에 대한 모든 정보를 통합하는 구조화된 데이터 객체입니다.

### 엔티티 다이어그램

```
┌─────────────────────────────────────┐
│          PlaceCard                   │
├─────────────────────────────────────┤
│ • id (UUID)                          │
│ • name, category, address            │
│ • coordinates (lat, lng)             │
│ • rating, reviewCount, phone, website│
│ • hoursDetail, closingTime, holidays │
│ • amenities[], tags[]                │
│ • media (MediaBundle)          ──────┼──► 1. mapScreenshots[]
│ • sources (SourceRecord[])     ──────┼──► 2. officialPhotos[]
│ • discoverySource (optional)   ──────┼──► 3. onsitePhotos[]
│ • createdAt, updatedAt         ──────┼──► 4. receivedPhotos[]
└─────────────────────────────────────┘
```

## 2.2 Swift 데이터 모델 정의

### 2.2.1 PlaceCard (메인 엔티티)

```swift
struct PlaceCard: Identifiable, Codable {
    // 식별자
    let id: String  // UUID 또는 ULID
    
    // 기본 정보
    var name: String                    // 상호명
    var category: String?               // \"카페\", \"음식점\" 등
    var address: String                 // 전체 주소
    
    // 위치 정보
    var coordinates: Coordinates?       // 위도, 경도
    
    // 평가/리뷰 정보 (주로 Google/Naver에서 제공)
    var rating: Double?                 // 평점 (1.0-5.0)
    var reviewCount: Int?               // 리뷰 수
    
    // 연락처 정보
    var phone: String?
    var website: String?
    
    // 영업 정보
    var hoursDetail: [String: String]?  // {\"Monday\": \"10:00-22:00\", ...}
    var closingTime: String?            // \"22:00\" (단순 표기)
    var holidays: String?               // \"매주 월요일 휴무\"
    
    // 편의시설 정보 (Google Places의 세부 속성)
    var amenities: [String]             // [\"주차 있음\", \"반려동물 동반가능\", ...]
    
    // 사용자 정의
    var tags: [String]                  // [\"카페\", \"강남역 근처\", \"사진 맛집\", ...]
    
    // 미디어 (4가지 출처별 분류)
    var media: MediaBundle
    
    // 출처 이력
    var sources: [SourceRecord]
    
    // SNS 발견 정보 (선택사항)
    var discoverySource: DiscoverySource?
    
    // 메타데이터
    var createdAt: Date
    var updatedAt: Date
}
```

### 2.2.3 MediaBundle (4가지 출처별 미디어 분류)

```swift
struct MediaBundle: Codable {
    /// 1. 지도 앱 스크린샷 (Google, Naver, Kakao 통합)
    var mapScreenshots: [MediaItem] = []
    
    /// 2. 지도 API에서 제공하는 공식 업체 사진
    var officialPhotos: [MediaItem] = []
    
    /// 3. 사용자가 해당 장소에서 직접 촬영한 사진
    var onsitePhotos: [MediaItem] = []
    
    /// 4. 다른 사용자가 전달한 사진
    var receivedPhotos: [MediaItem] = []
}

struct MediaItem: Codable, Identifiable {
    let id: String                      // UUID
    var localPath: String               // 앱 샌드박스 내 경로
    var url: String?                    // 네트워크 URL (있는 경우)
    var caption: String?                // 사용자 메모
    var uploadedAt: Date                // 추가된 시각
    var source: SourceType              // 어디서 온 미디어인지
}
```

### 2.2.4 SourceType (출처 구분)

```swift
enum SourceType: String, Codable {
    // 지도 스크린샷
    case naverMapScreenshot             // 네이버 지도 스크린샷
    case googleMapScreenshot             // 구글 지도 스크린샷
    case kakaoMapScreenshot              // 카카오맵 스크린샷
    
    // 지도 공유 정보 (딥링크)
    case naverMapShare                  // 네이버 지도 공유
    case googleMapShare                 // 구글 지도 공유
    case kakaoMapShare                  // 카카오맵 공유
    
    // 지도 API 직접 조회
    case googleDirectLookup             // Google Places API
    case naverDirectLookup              // Naver API
    case kakaoDirectLookup              // Kakao API
    
    // 사용자 촬영
    case onsitePhoto                    // 현장 촬영 사진
    case receivedPhoto                  // 전달받은 사진
    
    // SNS
    case instagramScreenshot            // 인스타그램 스크린샷
}
```

### 2.2.5 SourceRecord (출처 이력)

```swift
struct SourceRecord: Codable, Identifiable {
    let id: String                      // UUID
    var sourceType: SourceType
    var timestamp: Date
    var dataProvided: [String]          // [\"name\", \"address\", \"rating\", ...]
    var confidence: Double?             // 0.0-1.0 신뢰도 (AI 분석인 경우)
    var notes: String?                  // \"Google API에서 별도 확인 필요\" 등
}
```

### 2.2.6 DiscoverySource (SNS 발견 정보)

```swift
struct DiscoverySource: Codable {
    var platform: String               // \"instagram\", \"tiktok\", \"blog\" 등
    var screenshotPath: String?        // 발견한 스크린샷 경로
    var extractedCaptionText: String?  // Claude가 추출한 캡션
    var originalPostUrl: String?       // 포스트 URL (가능한 경우)
    var extractionConfidence: Double?  // Claude 추출 신뢰도 (0.0-1.0)
    var discoveredAt: Date             // 발견 시각
}
```

## 2.3 데이터 흐름 및 채워지는 과정

### 시나리오 1: 지도 스크린샷 추가

```
[사용자가 갤러리에서 스크린샷 선택]
         ↓
[Vision으로 텍스트 인식 (위치명, 주소 등 추출)]
         ↓
[Google Places API로 검증]
    ✓ 매칭 성공 → 상세 정보 채우기
    ✗ 매칭 실패 → 수동 입력 요청
         ↓
[PlaceCard 생성]
  - name, address, coordinates: Google API 응답
  - rating, reviewCount, phone, website, hoursDetail: Google API 응답
  - media.mapScreenshots[0]: 사용자가 선택한 스크린샷
  - sources[0]: SourceRecord(sourceType: .googleMapScreenshot, ...)
  - createdAt: now
```

### 시나리오 2: 인스타그램 스크린샷 추가

```
[사용자가 인스타그램 스크린샷 추가]
         ↓
[Claude API로 위치명 후보 추출 (이미지+캡션 분석)]
         ↓
[사용자에게 \"이 위치 맞나요?\" 확인 요청]
         ↓
[Google Places API로 최종 검증]
         ↓
[PlaceCard 생성]
  - discoverySource: DiscoverySource(
      platform: \"instagram\",
      extractedCaptionText: \"...\",
      extractionConfidence: 0.95
    )
  - sources[]: 
      - SourceRecord(sourceType: .instagramScreenshot, ...)
      - SourceRecord(sourceType: .googleDirectLookup, ...)
```

### 시나리오 3: 현장 촬영 사진만 있는 경우

```
[사용자가 현장 촬영 사진만 추가]
         ↓
[사용자가 수동으로 장소명/주소 입력]
         ↓
[Google Places API로 검증 (선택사항)]
         ↓
[PlaceCard 생성]
  - name, address, coordinates: 사용자 입력 (또는 Google 보강)
  - media.onsitePhotos[]: [사용자가 촬영한 사진들]
  - sources[0]: SourceRecord(sourceType: .onsitePhoto, ...)
```

## 2.5 데이터 검증 규칙

### 필수 필드
- `id`: UUID 또는 ULID (중복 불가)
- `name`: 최소 2자 이상
- `address`: 최소 5자 이상
- `media`: 최소 1개 이상의 MediaItem 포함

### 선택 필드
- `coordinates`: 위도/경도가 유효한 범위인지 검증 (-90~90, -180~180)
- `rating`: 1.0 <= rating <= 5.0
- `reviewCount`: >= 0

### 비즈니스 로직
- PlaceCard 생성 시 `createdAt` 자동 기록
- 수정할 때마다 `updatedAt` 자동 갱신
- `sources` 배열은 비워질 수 없음 (최소 1개 SourceRecord 필요)
