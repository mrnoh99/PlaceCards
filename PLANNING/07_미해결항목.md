### 1.2 카카오 로컬 API 저장 정책 공식 확인

**현황**:
- devtalk.kakao.com 답변에서 "구조화된 데이터 영구 저장 금지" 확인됨
- 하지만 최신 정책인지, 예외 사항은 없는지 확실하지 않음

**필요 작업**:
- [ ] Kakao Developers 공식 채널에 서면 문의 제출
  - 질문: "PlaceCard 스타일의 구조화된 정보(이름, 주소, 평점 등)를 로컬 DB에 저장하는 것이 정책상 허용되는가?"
  - 별도 예외 신청 가능 여부
- [ ] 답변 수령 및 법무 검토
- [ ] 카카오 활용 전략 최종 결정
  - Option A: 재조회 전략 (저장 안 함)
  - Option B: Google 중심, Kakao는 발견 출처용
  - Option C: 예외 신청 후 저장

**담당**: PM / 기술 리드
**마감**: 백엔드 설계 단계 전

- [ ] Kakao Developers 가입
  - REST API 키 발급

## 7.2 우선순위 2 (개발 시작 전)

### 2.1 백엔드 프록시 서버 아키텍처 상세 설계

**현황**:
- 개요만 정의됨 (Naver/Kakao용 프록시 필요)
- 구체적 구현 방식은 미정

**필요 작업**:
- [ ] 기술 스택 최종 결정
  - Node.js + Express (추천)
  - Python + Flask
  - Go
  - 다른 언어

- [ ] 프록시 서버 상세 설계
  - Endpoint 정의 (/api/naver/search, /api/kakao/search 등)
  - Request/Response 형식
  - 에러 처리 및 재시도 로직
  - Rate limiting 전략
  - 로깅 및 모니터링
  - CORS 설정

- [ ] 배포 플랫폼 선정
  - Heroku (유료화됨, $7/월+)
  - Railway ($5/월~)
  - Render
  - AWS Lightsail
  - 자체 VPS (Linode, DigitalOcean, Vultr)
  - 한국 로컬 호스팅 (Naver Cloud, AWS 서울)

- [ ] 보안 설계
  - API 키 관리 (환경 변수, .env 파일)
  - HTTPS/TLS 설정
  - API 요청 인증 (앱 서명 검증 등)
  - DDoS 보호
  - 로깅 시 민감정보 마스킹

**담당**: 백엔드 개발자
**마감**: 백엔드 개발 시작 전

---

### 2.2 Vision Framework OCR 파싱 로직 상세 설계

**현황**:
- Vision으로 텍스트 추출 가능함은 확인
- 구체적 파싱 규칙 및 정확도는 미정

**필요 작업**:
- [ ] 각 지도 앱별 스크린샷 특성 분석
  - Google Maps: 어디에 위치명이 표시되는가?
  - Naver Map: 위치 버튼 위치, 폰트, 크기
  - Kakao Map: 차이점
  
- [ ] OCR 파싱 규칙 정의
  - 위치명 후보 추출 알고리즘
  - 주소 분해 (시/도, 구/군, 동/읍, 상세주소)
  - 신뢰도 점수 계산 방식
  
- [ ] 테스트 데이터 수집
  - 각 앱별 스크린샷 50-100장
  - 다양한 위치 (카페, 음식점, 관광지, 편의점 등)
  - 다양한 화면 크기/각도
  
- [ ] 정확도 벤치마크
  - 목표: 80% 이상 정확도
  - 실패 케이스 분석 및 개선

**담당**: 개발자 (iOS)
**마감**: UI 구현 전

### 2.3 SwiftUI 화면 와이어프레임 및 상세 설계

**현황**:
- 뷰 계층 구조만 정의됨
- 구체적 레이아웃, 컴포넌트, 애니메이션 미정

**필요 작업**:
- [ ] 각 화면별 와이어프레임 (Figma/Sketch)
  1. OnboardingView (3단계)
  2. HomeView (최근 장소, 빠른 추가, 검색)
  3. GalleryView (그리드/리스트 전환)
  4. MapView (지도 + 마커)
  5. SettingsView (API 키, 정책, 내보내기, 정보)
  6. PlaceCardDetailView (상세 정보, 갤러리, 편집)

- [ ] 디자인 시스템 정의
  - 색상 팔레트 (primary, secondary, accent, neutral)
  - 타이포그래피 (body, headline, caption 등)
  - 버튼 스타일
  - 아이콘 셋
  - 간격/마진 규칙

- [ ] 사용자 흐름 (User Flow)
  - 처음 설치 → 온보딩 → 첫 PlaceCard 추가
  - 갤러리 → 검색 → 상세보기 → 편집
  - 설정 → API 키 등록

- [ ] 접근성 (Accessibility)
  - VoiceOver 지원
  - Dynamic Type 지원
  - High Contrast 모드

**담당**: 디자이너 / iOS 개발자
**마감**: UI 구현 단계 시작 전

  - 백업 및 복구 전략
  
- [ ] 성능 테스트
  - 500, 1000, 5000개 PlaceCard 저장 시 성능
  - 검색 및 필터링 성능

**담당**: iOS 개발자
**마감**: 데이터 계층 구현 단계

### 3.3 Export 기능 상세 정의

**현황**:
- \"JSON/CSV 내보내기\" 정도만 언급
- 어떤 필드를 포함할지, 어떤 형식일지 미정

**필요 작업**:
- [ ] Export 포맷 정의
  - JSON: 모든 필드 포함 vs 선택 필드만
  - CSV: 행/열 구조 결정
  - Excel: 스타일링 포함 여부
  
- [ ] 타겟 앱 연동
  - Google Sheets 직접 푸시
  - Notion 연동 (Notion API)
  - Airtable 연동
  - 일반 클라우드 드라이브 (iCloud, Google Drive, OneDrive)
  
- [ ] 필터링 및 선택
  - 모든 PlaceCard vs 특정 카테고리만
  - 날짜 범위 선택
  - 미디어 포함/제외

**담당**: iOS 개발자
**마감**: 최종 기능 단계
