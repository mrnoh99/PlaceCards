# 1. 프로젝트 개요

## 1.1 프로젝트 목표

여행/나들이 준비 과정에서 사용자가 여러 출처(지도 앱, SNS, 직접 촬영)를 통해 발견한 장소 정보를 하나의 통일된 카드(PlaceCard) 형식으로 저장, 관리, 조회, export할 수 있는 iOS 네이티브 앱 개발.

### 핵심 가치 제안
1. **통합 관리**: 분산된 장소 정보를 한 곳에서 체계적으로 관리
2. **스마트 발견**: 스크린샷 자동 스캔 + AI 기반 위치 인식
3. **정보 보강**: 여러 지도 API를 조합하여 가장 풍부한 정보 제공
4. **여행 계획 지원**: 수집한 장소를 기반으로 여행 계획 수립

---

## 1.2 타겟 사용자

- **주요**: 자유로운 여행/나들이를 좋아하고 SNS에서 발견한 장소를 수집하는 20-40대 여성
- **부가**: 출장/여행 준비가 빈번한 전문직 (컨설턴트, 영업)
- **확장**: 음식점/카페 애호가, 로컬 탐방 커뮤니티

---

## 1.3 주요 기능

| # | 기능 | 설명 | 우선순위 |
|---|------|------|---------|
| 1 | 스크린샷 스캔 | 지도/SNS 스크린샷에서 자동으로 장소명 추출 | P0 |
| 2 | PlaceCard 생성 | 추출된 정보를 구조화된 카드로 저장 | P0 |
| 3 | API 검증 및 보강 | Google/Naver/Kakao API로 정보 검증 및 추가 | P0 |
| 4 | 갤러리 뷰 | 저장된 PlaceCard를 카드 형태로 브라우징 | P0 |
| 5 | 지도 뷰 | 저장된 장소를 지도상에 마커로 표시 | P1 |
| 6 | 검색/필터 | 태그, 카테고리, 위치별 검색 | P1 |
| 7 | Export | JSON/CSV로 내보내거나 공유시트로 연동 | P1 |
| 8 | 설정/API키 관리 | 사용자가 API 키를 Keychain에 안전히 저장 | P0 |

## 1.4 개발 환경

### 필수 요구사항
- **OS**: iOS 15.0 이상
- **언어**: Swift 5.9+
- **IDE**: Xcode 15.0+
- **아키텍처**: SwiftUI + MVVM

### 외부 의존성
- **지도 API**: Google Places, Naver Map, Kakao Local
- **AI API**: Anthropic Claude (Vision + Text)
- **로컬 저장**: SwiftData 또는 CoreData
- **보안**: Keychain Services

### 백엔드 (선택사항)
- **Naver/Kakao용 프록시**: Node.js + Express
- **배포**: Heroku, Railway, 또는 VPS

## 1.6 성공 기준

### 기능적 성공
- [ ] 3개 이상 지도 앱(Google, Naver, Kakao)의 스크린샷 정상 분석
- [ ] 인스타그램 스크린샷에서 위치명 80% 이상 정확도로 추출
- [ ] 로컬 저장소에 500개 이상 PlaceCard 안정적 저장
- [ ] 지도 뷰에서 100개 이상 마커 렌더링 (성능 목표: <2s)

### 보안/사용자 신뢰
- [ ] API 키는 Keychain에만 저장 (UserDefaults 절대 금지)
- [ ] BYOK 모델 구현 — 사용자가 자신의 API 키 등록
- [ ] Privacy Nutrition Label 정확히 표기

### 사용자 경험
- [ ] 온보딩 완료 시간: 3분 이내
- [ ] PlaceCard 생성 시간: 스크린샷 촬영 후 10초 이내
- [ ] 앱 크기: 50MB 이하

## 1.8 예산 및 일정 (참고)

### 개발 비용 (추정)
- **Google Places API**: 월 $1-50 (사용량에 따라, BYOK이면 사용자 부담)

- **iOS 개발**: 개발자 계정 (연 $99)

- **설계 단계**: 2-3주
- **코드 개발**: 8-12주
- **테스트/QA**: 2-3주
- **배포 준비 및 심사**: 2-4주
- **전체**: 약 4-5개월
